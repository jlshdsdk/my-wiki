04 · Markdown：为什么全世界写文档都用它 ​

一句话说清这课解决什么问题：让你看懂并能亲手写出 Wiki 页面里那些 #、**、- 符号——你正在写的整个网站，本质就是一堆这样的文本文件。

它是什么？（大白话 + 生活比喻） ​

Markdown 是一种「用纯文本符号来表示排版」的写作格式。它不是软件，而是一套约定：你写下某些符号，阅读工具（比如你的 VitePress 网站）就会把它们变成漂亮的排版效果。

生活比喻：Markdown 就像发微信时的「暗号」。你给朋友发一句「我今天 特别 开心」，那两颗星在聊天框里就是两颗星，但很多软件会默契地把 **特别** 显示成加粗。你只管按暗号写字，显示效果由软件负责——这就是 Markdown 的全部思想。

几个最常用的暗号：

  • # 开头的行 → 大标题（## 是二级标题，以此类推）
  • **文字** → 加粗，*文字* → 斜体
  • - 开头的行 → 无序列表（就是前面带圆点的列表）

为什么我们需要它？ ​

想想你正在做的事：

  1. 你的 Wiki 就是一堆 .md 文件。VitePress 不需要你去点鼠标排版，它读这些文本文件，直接变成 https://jlshdsdk.github.io/my-wiki/ 上的漂亮网页。
  2. 纯文本永远打得开。Word 文档换个软件可能乱码，而 .md 用记事本就能打开，再过二十年也一样。
  3. Git 能看清你每次改了哪一行。以后你把 Wiki 推到 GitHub（你的用户名是 jlshdsdk），每次修改都能精确显示「第几行从什么改成了什么」。如果是 Word 的二进制文件，Git 根本看不懂。

也就是说：Markdown 是「人好写、机器好读、版本管理好对比」的三赢格式，所以全世界的笔记、文档、README 都用它。

动手试一试 ​

下面是一段自我介绍，我们逐句给它加上 Markdown 语法（新建一个 test.md，抄进去，然后拖进 VS Code 预览）：

markdown
## 关于我

我是 **jlshdsdk**，正在从零学 *大模型应用开发*。

- 平时用 Windows 11 写笔记
- 目标是做一个自己的知识库网站

我的 Wiki 在这里：[我的 Wiki](https://jlshdsdk.github.io/my-wiki/)

```python
print("Hello, Markdown!")
```

逐句解释：

  • ## 关于我 → 二级标题，页面上会显示为大字。
  • **jlshdsdk** → 加粗；*大模型应用开发* → 单星是斜体，注意区别。
  • - 平时用…… → 两行列表，渲染后前面会有圆点。
  • [我的 Wiki](网址) → 方括号写显示文字，圆括号放链接地址，合起来是超链接。
  • 最后那对三个反引号包住的是代码块，开头反引号后面写 python，还能自动语法高亮。

VitePress 的扩展：容器语法 ​

你的站点是 VitePress，它在标准 Markdown 之上加了几种「提示盒子」，写法是三个冒号：

markdown
::: tip 小提示
这里写提示内容，会渲染成一个绿色提示框。
:::

::: warning 注意
这是黄色警告框。
:::

::: details 点我看答案
这是可折叠的内容，点标题才展开。
:::

frontmatter：文件最上面的「档案卡」 ​

你可能注意到本文件开头有两行 ---，中间夹着 title: ...。这叫 frontmatter——文件最顶部两条三横线之间放的「元信息」（关于这个文件的信息，而不是正文）。VitePress 会读它来设置页面标题、侧边栏顺序等。记住：frontmatter 必须是文件的第一行就开始，不能前面有空内容。

常见报错与怎么读它 ​

Markdown 没有编译器，不会弹红色报错，但有一种极常见的「排版事故」——代码块没闭合。假设你写了：

markdown
```python
print("hello")
```

上面忘了写结尾的 ```（或者结尾多打了一个），从这行往后……

如果你写了开头三个反引号 ```，却忘了写结尾三个，那么 Markdown 会认为「从这行开始全是代码」，于是后面整页的文字都变成等宽字体的灰色代码块，标题、加粗全部失效，页面排版全乱。

怎么从「渲染结果怪异」倒推原因？按这三步排查：

  1. 找到排版开始变怪的那个位置——从哪一行开始不对劲？
  2. 看那一行的上方，找配对符号：三个反引号是不是只有开头没有结尾？** 是不是只有一半？表格的 | 是不是漏了分隔行？
  3. 记住「符号要成对」：```、**、::: 这些都是开门要关门。逐个检查，几乎百发百中。

排查小技巧：在 VS Code 里按 Ctrl+Shift+V 打开预览，一边改一边看，乱掉的范围就是你的「案发现场」。

自测两题 ​

第 1 题：想把一句话里某个词加粗并且变成可点击的链接，符号该怎么组合？

点击看答案

加粗套在链接文字外面：[**加粗的链接**](https:// example.com)（实际使用时网址里不要有空格）。核心思路是 Markdown 语法可以嵌套：[显示文字](网址) 里的「显示文字」部分再用 ** 包起来即可。

第 2 题：你的页面从中间某处开始全部变成了灰色等宽字体，正文排版全没了，最可能的原因是什么？

点击看答案

某个代码块的结尾三个反引号 ``` 丢了（或者数量不配对），导致 Markdown 认为后面全是代码。定位方法：从排版开始乱的那行往上找，找到最近一个代码块开头，补上成对的结尾即可。
