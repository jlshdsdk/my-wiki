01 · 命令行：学会用打字指挥电脑 ​

一句话说清这课解决什么问题：让你不再怕那个黑乎乎的窗口，能站在正确的文件夹里敲出正确的命令——这是后面装工具、建网站、用 Git 的地基。

它是什么？（大白话 + 一个生活比喻） ​

平时你用电脑，是靠鼠标点图标、拖文件，这叫图形界面——像在餐厅看着菜单图片点菜。

命令行则是另一个路子：你打开一个黑窗口，用打字的方式给电脑下指令，电脑打字回答你。它像去老字号饭馆直接跟掌柜喊话：「来二两牛肉面！」——不用看图，说一句话，事就办了。掌柜（电脑）话不多，但快、准，而且什么后厨的活（装软件、建文件、查状态）都能给你干。

在 Windows 上，这个黑窗口的程序叫 cmd（命令提示符）。本课所有命令都是 cmd 写法。

为什么我们需要它？（和你要做的 Wiki/大模型项目挂钩） ​

你正要搭的 Wiki 网站用 VitePress（一个把 Markdown 变成漂亮网站的工具），它没有「双击安装」这种东西——你得在命令行里敲一行命令启动它。后面学大模型应用开发，装库、跑脚本、调 API，几乎全在命令行里完成。

一句话：命令行是程序员的门厅，进屋（做项目）之前必须会开这扇门。

动手试一试（核心命令） ​

先打开命令行：按 Win + R，输入 cmd，回车。弹出来的黑窗口就是命令行。

先理解一个概念：工作目录——你现在「站在」哪个文件夹里。命令行里每条命令都是对当前站着的文件夹说的，就像你跟掌柜说「看看货」时，掌柜只会看你手边这间仓库。

bat
cd C:\Users\王奕博\Desktop
rem 走到桌面这个文件夹（cd = change directory，改变工作目录）

md test-folder
rem 新建一个叫 test-folder 的文件夹（md = make directory）

cd test-folder
rem 走进刚建的文件夹

dir
rem 列出当前文件夹里的内容（dir = directory），现在是空的

cd ..
rem 退回上一层（.. 就是「上一层文件夹」）

rd test-folder
rem 删掉 test-folder（rd = remove directory，只能删空文件夹）

cls
rem 清屏，把窗口里的字全擦掉，还你一片干净（cls = clear screen）

试完你会发现：文件夹建了又删了，电脑毫发无损。命令行没那么可怕，敲错了顶多报个错，不会炸。

常见报错与怎么读它 ​

真实案例（你以后几乎必遇到）：

'git' 不是内部或外部命令，也不是可运行的程序或批处理文件。

怎么读这条报错？拆三段看：

  1. 'git'——引号里是你敲的那个词，说明电脑是对「git」这个词没反应，不是你敲错了格式。
  2. 不是内部或外部命令——「内部命令」是 cmd 自带的（如 dir、cd），「外部命令」是装在电脑上的程序。这句的意思是：两拨人里都没找到叫 git 的。
  3. 也不是可运行的程序或批处理文件——连当前文件夹里也没有 git.exe。

为什么找不到？这里就要讲环境变量和 PATH 了。

环境变量是 Windows 给系统和程序准备的一批「全局备忘」，其中最重要的一条就是 PATH：它是系统的一张「地址簿」，里面记着一串文件夹。你敲一个命令名（比如 git），系统就按地址簿挨个文件夹去找有没有 git.exe——找到了就运行，翻遍地址簿都没有，就报上面那个错。

所以这条报错的真正含义通常是：git 装了，但它的文件夹没写进 PATH 地址簿，或者压根没装。

解决办法有两条路：

  • 把 git 所在的文件夹加进 PATH（图形界面操作：设置 → 系统 → 关于 → 高级系统设置 → 环境变量，在 Path 里「新建」一条文件夹路径）。
  • 或者干脆每次敲完整路径，比如 C:\工具\git\cmd\git.exe --version（直接报出完整门牌号，系统就不用查地址簿了）。

顺便说下便携版：就是不用安装器、解压就能用的软件。好处是干净、随拷随走；代价是它不会在安装时自动「登记户口」（写进 PATH），所以经常要你手动加地址簿——这正是你遇到上面报错的原因。

自测两题 ​

第 1 题：cd .. 是干什么的？

看答案

退回上一层文件夹。比如你站在 Desktop\test-folder 里，敲 cd .. 后就回到了 Desktop。可以连着用：cd ..\.. 是退两层。

第 2 题：为什么敲 git 会报「不是内部或外部命令」，但敲 dir 就有反应？

看答案

dir 是 cmd 的内部命令，自带随身，永远找得到；git 是外部程序，系统要去 PATH 地址簿里逐个文件夹找 git.exe。找不到就报这个错——说明 git 没装，或它的文件夹不在 PATH 里。
