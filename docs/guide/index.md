# 我的学习路线图

> 主方向已定：**大模型应用开发**。这一页是我的总地图：每完成一个里程碑就回来勾掉一项，每学会一个新概念就把它加进[术语表](/glossary/)。

## 我的起点与终点

- **起点**：编程只会一点皮毛，Git、命令行、Python 都在从头学。
- **终点**：能独立做出「调用大模型 API、解决真实问题」的应用，并把整个过程沉淀成这座 Wiki。

## 总览：三个阶段，一条主线

```txt
API 调用与聊天助手 ──→ RAG 知识库问答 ──→ Agent 智能体
 （一切应用的地基）    （业界最主流形态）   （让 AI 会用工具）
```

为什么是这个顺序？因为它们是**叠层**关系：

- 阶段二的 RAG，本质是「阶段一的 API 调用」前后各加一步——先去资料库里**检索**相关段落，再拼进提问里发出去；
- 阶段三的 Agent，本质是「阶段一的 API 调用」套上一个**循环**——模型说要调工具 → 我们执行 → 把结果喂回去 → 模型继续，直到它说做完了；
- 地基不牢，上面全塌。所以宁可阶段一慢一点，也要把 HTTP、API、Prompt 这些概念真正吃透。

## 阶段一 · API 调用与聊天助手

**要解决的问题**：怎么用代码和一个大模型「对话」？

**要学会的知识点**：

- **API** 与 **API Key**：程序怎么安全地调用别家服务
- **HTTP** 请求的 GET / POST，**JSON** 数据格式
- **Prompt**（提示词）：怎么把话说清楚，让模型稳定干活
- **流式输出**：为什么 AI 的回答是一个字一个字蹦出来的
- **上下文**与多轮对话：模型没有记忆，「记忆」是我们每次把历史聊天一起发过去
- **Token**（词元）：按什么计费、上下文为什么有长度上限

**里程碑产出**：一个能连续对话、支持流式输出的命令行聊天助手（约 100 行 Python）。

## 阶段二 · RAG 知识库问答

**要解决的问题**：大模型没读过「我自己的文档」，还会一本正经地编（**幻觉**）。怎么让它拿着我的资料、只根据我的资料回答？

**要学会的知识点**：

- **Embedding**（向量嵌入）：把文字变成一串数字，意思越近的文字，数字之间越「近」
- **向量检索**：用数字之间的距离，找出语料里最相关的几段话
- **文档切片**：为什么长文档要先切成小块再入库
- **RAG**（检索增强生成）完整流程：切片 → 向量化 → 检索 → 拼进 Prompt → 生成

**里程碑产出**：一个「扔进几篇自己的文档，就能针对它们问答」的本地知识库（约 150 行 Python）。

## 阶段三 · Agent 智能体

**要解决的问题**：模型只会「说」，不会「做」。怎么让它会查天气、会算数、会搜网页？

**要学会的知识点**：

- **Function Calling**（函数调用）：告诉模型「你有哪些工具、分别在什么时候用」
- **工具循环**：模型请求调工具 → 我们执行 → 结果喂回去 → 模型继续，直到它给出最终回答
- Agent 的适用边界：什么场景该用，什么场景是杀鸡用牛刀

**里程碑产出**：一个会自己决定「该调哪个工具」的小智能体（约 120 行 Python）。

## 为什么新手不推荐一上来就学「微调」和「推理部署」

这两条路不是不好，而是**不该成为新手的第一个 100 小时**：

**微调（Fine-tuning）**——修改模型本身的大脑：

- 要 GPU：微调需要昂贵显卡（自己买或云租都烧钱）；
- 要数学底子：损失函数、梯度、学习率……零基础阶段硬啃，事倍功半；
- 要数据工程：准备几百上千条高质量训练数据，本身就是一门手艺；
- 最关键的是：**绝大多数应用场景，写好 Prompt + 用好 RAG 就已经够了**。先用起来，等你真正遇到「Prompt 解决不了」的问题再学微调，带着问题学最快。

**推理部署（Inference Deployment）**——把模型跑起来对外提供服务：

- 本质偏运维：显存管理、模型量化、并发吞吐、vLLM 这类框架的使用与调优；
- 应用开发者直接调用现成 API（比如智谱 GLM 开放平台）就能拿到同样的模型能力；
- 它其实是另一条职业路线（推理优化工程师），和「做应用」是两个工种。

一句话总结：**先学会「用」模型做应用，再考虑「改」模型和「跑」模型。**
