# 03 · Git 与 GitHub：给代码装一台时光机

> 一句话说清这课解决什么问题：学会用 Git 给项目拍「快照」，改坏了能随时回头；再用 GitHub 把快照同步到云端，让全世界能看到你的 Wiki。

## 它是什么？（大白话 + 一个生活比喻）

**Git** 是一个**版本控制**工具——说人话，就是**给文件夹拍快照的时光机**。你每改完一版代码，就拍一张快照存档；哪天改崩了，随时翻回任何一张旧快照。再也不用靠「最终版」「最终版2」「真的最终版」这种文件名续命了。

**GitHub** 是一个网站，作用是**存快照的云端仓库**，同时也是全球程序员交流的平台。你把本地的快照传上去，既算备份，也能分享给别人。

一句话分清：**Git 是装在你电脑上的工具（相机），GitHub 是网上的存照平台（云端相册）**。两者经常一起用，但完全不是一回事——就像相机和朋友圈的关系。

## 为什么我们需要它？（和你要做的 Wiki 挂钩）

你的 Wiki 站点代码会越写越多，难免有「改着改着改崩了」的时刻——有了 Git，一条命令就能回到昨天的好状态。更关键的是发布：你的线上地址 https://jlshdsdk.github.io/my-wiki/ 用的就是 **GitHub Pages**（GitHub 提供的免费静态网站托管），它直接从你 GitHub 上的仓库读文件来生成网页。所以流程必然是：本地改 → Git 存快照 → 推上 GitHub → 网站自动更新。

这里的几个术语先用相册比喻打个底：

- **仓库**（repository）：被 Git 管起来的文件夹，相册本子本身。
- **暂存（add）**：从一堆改动里**选出这次要拍的照片**——不是所有改动都想进这一页。
- **提交（commit）**：把选好的照片**贴成一页，并在页边写注释**——这页改了啥。每个 commit 都是一张快照。
- **推送（push）**：**把相册同步上云**，传到 GitHub。
- **克隆（clone）**：**从云端复印整本相册**到本地——通常是你在新电脑上拿到一个项目的第一步。

另外还有 **GitHub Actions**（GitHub 的自动机器人，可以帮你每次推送后自动构建网站）和**部署**（把做好的网站放到能访问的地方）这两个词，后面建站课会见到，现在混个脸熟即可。

## 动手试一试（核心命令）

空口学不会，来真练一遍。打开 cmd：

```bat
cd C:\Users\王奕博\Desktop
rem 先走到桌面（站在正确的工作目录里）

md test-repo
rem 建一个练手文件夹

cd test-repo
rem 走进它

git init
rem 在这个文件夹里「建相册」：初始化一个新仓库

git status
rem 看看现在有哪些改动还没进相册（此时应该是空的）

echo hello > note.txt
rem 建一个测试文件，内容是 hello

git add note.txt
rem 暂存：把 note.txt 选出来，作为这次要拍的照片

git commit -m "第一次练习提交"
rem 提交：把选好的照片贴成一页，-m 后面是这页的注释

git log
rem 翻相册：列出所有历史快照，能看到刚才那条注释
```

走完这四步（init → add → commit → log），你就完成了一次标准的 Git 工作流。日常写 Wiki 就是这个循环的重复：改文件 → add → commit → push。

练完了删掉练手文件夹即可（`cd ..` 后 `rd /s test-repo`，`/s` 表示连里面的文件一起删）。

## 常见报错与怎么读它

真实案例：

```
fatal: not a git repository
```

怎么读？

1. `fatal`——「致命错误」，意思是这条命令没法继续，直接停了。
2. `not a git repository`——直译「这里不是一个 git 仓库」。翻译成相册比喻：**你还没建相册，就用了相册命令**。比如你在一个普通文件夹里直接敲 `git add` 或 `git commit`，Git 一看：这文件夹我没管着，没法办。

排查思路：

- 先敲 `git status` 确认自己是不是站在仓库里。如果报同样的错，说明这个文件夹没被 Git 管理。
- 常见原因是**走错了文件夹**——仓库其实在子目录里，你人在外面。用 `dir` 看看有没有 `.git` 文件夹（它就是相册本子的实体，Git 靠它认仓库）。
- 真没建过，就 `git init` 先建相册。

这个报错其实很友好：它不破坏任何东西，只是拒绝干活，照着提示补一步就好。

## 自测两题

**第 1 题**：Git 和 GitHub 是一回事吗？各用一句话说明。

::: details 看答案
不是。Git 是装在电脑上的版本控制工具，负责给项目拍快照、回滚（相机）；GitHub 是存快照的云端网站，负责备份和分享（云端相册）。Git 离了 GitHub 也能用，GitHub 离了 Git 就没意义。
:::

**第 2 题**：add、commit、push 分别对应相册流程里的哪一步？为什么 commit 前要先 add？

::: details 看答案
add = 选出这次要拍的照片（暂存）；commit = 把照片贴成一页并写注释（提交快照）；push = 相册同步上云（推送到 GitHub）。commit 前先 add，是因为你可能同时改了五个文件，但只想让其中两个进这一页快照——add 就是那道「挑选」的闸门。
:::
