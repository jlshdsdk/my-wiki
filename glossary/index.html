工具与版本控制 ​

术语大白话解释
命令行用打字的方式给电脑下指令的界面（那个黑窗口），开发者的主要工作方式
工作目录命令行里你当前「站」在哪个文件夹；相对路径都从这里算起
环境变量操作系统层面的全局设置，像电脑的「公共便签」，程序都能读到
PATH一个特殊的环境变量：记录「去哪些文件夹找程序」的地址簿；找不到就报「不是内部或外部命令」
便携版解压即用、不写注册表的软件形态，可以放在任何文件夹（所以常要手动加 PATH）
Git版本控制工具：给文件夹拍快照的「时光机」，任何时刻可回看、可回滚
GitHub托管 Git 仓库的网站，程序员的「云端仓库 + 社交平台」
仓库（Repository / repo）被 Git 管理的项目文件夹，连同它的全部历史快照
暂存（add）挑选哪些改动要进入下一次快照
提交（commit）把暂存好的改动拍成一张快照，并附一句说明
推送（push）把本地的新快照上传到云端仓库（如 GitHub）
克隆（clone）把云端仓库完整复制到本地
分支（branch）平行的开发线，各改各的互不干扰，之后可合并（本站固定用 main 主分支）
token（令牌）访问 GitHub 等服务的「门禁卡」，卡上刻着权限范围（scope）；要像密码一样保密
YAML用缩进表示层级的配置文件格式，GitHub Actions 的工作流就用它写

建站与部署 ​

术语大白话解释
Node.js让 JavaScript 脱离浏览器、在电脑上独立运行的「舞台」
npmJavaScript 的包管理器：应用商店 + 快递员
依赖（dependency）项目里用到的别人写好的代码包
package.json项目的「采购清单 + 说明书」，npm 靠它知道装什么、怎么跑
镜像官方下载仓库的国内「分店」，物理距离近所以快（如 npmmirror、清华 pip 源）
VitePress静态网站生成器：把一堆 Markdown 文件变成带导航和搜索的漂亮网站
Markdown用纯文本符号（#、**）写排版的标记语言，本站每一页都是它
frontmatter文件开头两条 --- 之间的小块元信息（如标题、布局），给程序看的不正文
静态网站服务器只发现成文件、不做现场计算的网站——快、稳、免费托管
部署（deploy）把网站或程序放到线上，让别人能访问
GitHub PagesGitHub 免费的静态网站托管服务，本站就住在这里
GitHub ActionsGitHub 的自动化流水线：代码一推送，自动跑构建、部署等脚本
CI/CD持续集成 / 持续交付的统称：推送代码后自动构建、检查、上线的工程实践

网络与 API ​

术语大白话解释
HTTP浏览器/程序与服务器之间沟通的协议，一对「点菜语言」
HTTPS加密版的 HTTP，内容在路上不被偷看
URL网址：协议 + 服务器地址 + 路径
GET / POSTHTTP 的两个常用动作：GET 取数据（看菜单），POST 交数据（下单）
状态码服务器回话的数字暗号：200 成功、404 没这页、401 没权限、500 服务器出错
JSON程序之间传数据的标准格式，"键": 值 的写法
API程序对程序开放的「服务窗口」，按约定格式发请求、拿响应
API Key调 API 的身份凭证（会员卡号），证明你是谁、给你记账；要保密

大模型（LLM） ​

术语大白话解释
LLM（大语言模型）读过海量文本、会续写会对话的 AI 模型，如 GLM、GPT
Prompt（提示词）发给模型的指令或问题；怎么问，很大程度决定答得怎么样
Token（词元）模型处理文字的最小单位（约 1 个汉字 = 1~2 个 token），也是计费和限长单位
上下文（context）一次请求里模型能「看到」的全部内容，有长度上限，超了就记不住
流式输出回答一边生成一边一段段传回来，而不是憋到最后一次性给
多轮对话把之前的聊天记录一起发过去，让模型「记得」聊过什么
幻觉（hallucination）模型一本正经地编造不存在的事实
Embedding（向量嵌入）把文字变成一串数字（向量），意思越近的文字，向量越「近」
RAG（检索增强生成）先去资料库检索相关段落，再塞给模型让它「看着资料回答」
Agent（智能体）能自主决定「调哪个工具、下一步做什么」的 AI 程序
Function Calling（函数调用）让模型按约定格式请求调用外部工具（查天气、算数、搜索）的机制
微调（fine-tuning）用自己的数据继续训练模型，改的是模型本身
推理（inference）用训练好的模型生成回答的过程（对应「训练」）

维护规则
